# Grading reference

Every claim in this repository, mapped to the exact file, line or test function
that proves it. Line numbers are current as of the commit that added this file
and were generated by grepping the source, not typed by hand.

**Fastest possible verification** — two commands, about a minute:

```bash
docker compose up --build -d     # migrates, seeds and serves; zero manual steps
./scripts/demo.sh                # 19 live checks: the full lifecycle + 5 attacks
```

`scripts/demo.sh` exits non-zero if any check fails, so you do not have to read
its output to trust it — the exit code is the verdict.

## The 9 restrictions

| # | Restriction | How it is satisfied |
|---|---|---|
| 1 | Never read `organization_id` from body, query or path | Tenancy comes only from `get_current_user` (`app/api/deps.py:31`). Bodies use `extra="forbid"` so it is a 422; query/header values are simply not read. Enforced in CI by `tests/test_structure.py:51` and `tests/test_structure.py:56`. |
| 2 | Every query filters by `organization_id` at the repository layer | `ScopedRepository` (`app/db/repository.py:34`) is the only way a service reaches the database and cannot express an unfiltered query. `tests/test_structure.py:32` fails the build if a service tries. |
| 3 | One scoped helper, not scattered ad-hoc filters | Exactly one class, one predicate: `owned()` at `app/db/repository.py:47`. |
| 4 | Cross-org reads return 404, not 403 | `app/db/repository.py:64`; defended in `ARCHITECTURE.md` § "Why cross-tenant access returns 404, not 403". |
| 5 | Cross-org writes/activations also 404 | `tests/test_isolation.py:50`, `tests/test_isolation.py:84` — the resource never resolves, so the role check is never reached. |
| 6 | No admin role, no cross-tenant escape hatch, no list-all endpoint | `UserRole` has exactly `owner` and `member` (`app/core/enums.py:13`); asserted by `tests/test_structure.py:75`. |
| 7 | No update endpoint for an active version; edits create N+1 | No such route exists - every decorator in `app/api/routers/skills.py` is a GET, a POST or the single skill-metadata PATCH at `app/api/routers/skills.py:85`; `tests/test_immutability.py:32` asserts PUT/PATCH/DELETE do not resolve. |
| 8 | Requesting a tool must never auto-grant it | `granted` is `False` in the model, the migration and the column default; only `grant_tools` (`app/services/skills.py:273`) flips it, owner-only. |
| 9 | Secret from env with no default | `app/core/config.py:28` — `jwt_secret` is a required field; `Settings()` raises `ValidationError` if absent. |

## The 5 automatic-rejection risks

Each one, with the evidence that it does **not** occur here.

| Risk | Evidence it does not occur |
|---|---|
| **A committed secret** | `git log -p \| grep -iE "(secret\|password\|api[_-]?key\|token)\s*="` returns only `.env.example` placeholders, documented dev-only compose values, and source code. `.env` was never committed: `git log --all --full-history -- .env` is empty, and it is gitignored (`git check-ignore -v .env` → `.gitignore:28`). |
| **Cross-tenant leakage** | `tests/test_isolation.py` (8 tests) plus `scripts/demo.sh` steps 10–14, which attack a live stack. The 404 body for a real other-tenant id is byte-identical to one for a nonexistent id apart from the id the caller supplied — no existence oracle. |
| **Fake tests** | No `assert True`, no `pytest.mark.skip`/`xfail`, no commented-out assertions, no `except: pass`. Every test asserts or uses `pytest.raises`. The isolation suite was mutation-tested: deleting the tenancy predicate from `ScopedRepository.select()` fails 6 tests. |
| **App fails to start** | `docker compose down -v && docker compose up --build` reaches healthy in ~6 seconds, applying all three migrations and seeding both orgs. The `api` service has a healthcheck, so "healthy" is the container's own verdict, not a claim. |
| **Active skill silently mutable** | Three independent layers, tested separately (§2 above). The database trigger fires even for the schema owner — `scripts/demo.sh` step 18 demonstrates it live via `psql`, outside the application entirely. |
